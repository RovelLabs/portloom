# Security Model & Threat Assessment

## 1. Общие принципы безопасности Portloom

Portloom оперирует на критически важном стыке: локальная операционная система (Windows), файл `hosts`, системные сетевые сокеты и локальное хранилище доверенных сертификатов X.509. 

Безопасность строится на трех фундаментальных принципах:
1. **Принцип наименьших привилегий (Least Privilege):** Ядро и интерфейс работают под правами обычного непривилегированного пользователя Windows.
2. **Нулевое внешнее воздействие (Air-Gapped by Design):** Управляющий порт (`127.0.0.1:24224`) намертво привязан к интерфейсу замыкания на себя (loopback). Прослушивание `0.0.0.0` для API управления запрещено.
3. **Безопасность по умолчанию (Safe Defaults):** Защита системных процессов Windows от случайного уничтожения, автоматическое резервное копирование системных файлов перед модификацией.

## 2. Модель угроз (Threat Model)

| Вектор угрозы | Описание риска | Архитектурная защита в Portloom |
|---|---|---|
| **Случайное убийство системных процессов Windows** | Попытка пользователя «освободить порт 80 или 443», на котором работает системная служба (`svchost.exe`, `System`, `lsass.exe`, `explorer.exe`). | Встроенный «черный список» системных PID и имен процессов. Попытка завершить системный процесс блокируется с явным предупреждением. Завершение возможно только для пользовательских процессов (Node, Python, Go, Java, Docker и т.д.). |
| **Command Injection через CLI/имена процессов** | Попытка внедрения управляющих символов оболочки (`&`, `;`, `\|`, powershell-команд) при парсинге PID или доменов. | Все системные вызовы используют прямое API `child_process.execFile` или строгую параметризацию аргументов без интерполяции строк в `cmd.exe` / `powershell`. |
| **Path Traversal при резервном копировании `hosts`** | Манипуляция путями для перезаписи критических файлов ОС. | Пути назначения формируются строго внутри изолированной директории `%APPDATA%\Portloom\`. Имена бэкапов содержат только временную метку и безопасные символы. |
| **Утечка приватного ключа локального Root CA** | Несанкционированный доступ сторонних вредоносных программ к закрытому ключу локального CA. | Закрытый ключ корневого сертификата (`ca.key`) генерируется с правами доступа `0600` (чтение только владельцем процесса). В документации явно объясняется зона ответственности локального CA. |
| **DNS Rebinding & Cross-Site Request Forgery (CSRF)** | Вредоносный сайт в браузере пытается слать запросы на `http://localhost:24224/api/kill` для завершения процессов. | API управления проверяет заголовок `Origin` / `Sec-Fetch-Site` и отклоняет любые внешние веб-источники. Поддерживается генерация локального Bearer-токена сессии. |
| **DoS через кольцевой буфер инспектора трафика** | Переполнение оперативной памяти при передаче огромных объемов данных через локальный прокси (например, скачивание файла 2 ГБ). | Потоковое проксирование (Stream Piping). Тело запроса/ответа логируется инспектором только до безопасного лимита (по умолчанию 1 МБ на запрос). Превышающие лимит данные проксируются прозрачно в потоке без буферизации в RAM. |

## 3. Обработка системных файлов Windows

### Файл `hosts` (`%SystemRoot%\System32\drivers\etc\hosts`)
1. **Предварительная валидация синтаксиса:** Проверка корректности IP-адресов (IPv4 / IPv6) и доменных имен по стандарту RFC 1123.
2. **Атомарная запись:** Данные записываются в `.tmp` файл в том же каталоге или временной папке и затем атомарно перемещаются.
3. **Неизменяемость пользовательских комментариев:** Парсер сохраняет исходные строки и порядок файла пользователя, инкапсулируя правила Portloom в четко маркированные блоки комментариев:
   ```hosts
   # --- BEGIN PORTLOOM MANAGED BLOCK [Profile: Default] ---
   127.0.0.1  my-app.local
   127.0.0.1  api.my-app.local
   # --- END PORTLOOM MANAGED BLOCK ---
   ```
4. **Откат (Rollback):** Возможность восстановить файл `hosts` из любого сохраненного бэкапа в 1 клик.

## 4. Разграничение прав администратора (UAC)

- Большинство операций (просмотр портов, завершение собственных процессов пользователя, запуск прокси на портах выше 1024, генерация сертификатов, просмотр трафика) **НЕ ТРЕБУЮТ прав администратора**.
- Запись в `C:\Windows\System32\drivers\etc\hosts` и привязка к низким системным портам (80 / 443) требуют повышенных привилегий в Windows. Portloom предоставляет:
  1. Либо запуск elevation-помощника через стандартный Windows UAC;
  2. Либо работу в режиме «User Port Mode» (например, прокси на порту 8443 без админа с понятной инструкцией).
